### 저장 설계
- sessionStorage에 저장한 값과 이유: 진행 중인 답변을 저장한다. 참여자 ID, 버전, 별명, 현재 문항 번호, 지금까지 선택한 답변을 저장하여 새로고침해도 같은 탭에서 이어할 수 있도록 했다. 탭을 닫으면 진행 중인 답변이 사라져야 하므로 sessionStorage를 사용했다.
- localStorage에 저장한 값과 이유: 완료한 결과 기록을 배열로 저장한다. 각 기록에는 ID, 버전, 별명, 전체 답변, 결과 유형, 완료 시간이 포함된다. 완료 기록은 탭을 닫거나 브라우저를 다시 열어도 남아야 하므로 localStorage를 사용했다.
- 내 데이터 조회·개별 삭제·전체 삭제 동작: `내 저장 데이터 보기`를 누르면 sessionStorage의 진행 중인 답변과 localStorage의 완료 기록을 화면에 표시한다. `이 기록 삭제`는 해당 ID의 기록만 배열에서 제거한 뒤 localStorage에 다시 저장한다. `게임 데이터 전체 삭제`는 진행 중인 답변과 완료 기록을 모두 삭제하고 화면도 초기화한다.

### 확인 결과
- 브라우저와 실험 조건: Chrome에서 GitHub Pages 주소를 열고 별명을 입력한 뒤, 일부 문항만 답한 경우와 10개 문항을 모두 답한 경우를 각각 확인했다. 개발자 도구의 Application 탭에서 sessionStorage와 localStorage의 저장 내용도 확인했다.
- 새로고침 / 독립적인 새 탭 / 탭 닫기 비교: 진행 중인 답변은 같은 탭에서 새로고침하면 남고, 독립적인 새 탭에서는 이어지지 않는다. 탭을 닫으면 sessionStorage의 진행 답변은 사라진다. 완료 기록은 localStorage에 저장되므로 새 탭이나 브라우저를 다시 열어도 같은 주소라면 남는다.
- 중복 저장 / 잘못된 데이터 / 삭제 후 재방문 확인: 같은 참여의 완료 기록은 ID를 확인하여 중복 저장하지 않는다. 버전, 답변 형식, 완료 시간, 결과 유형이 잘못된 기록은 불러올 때 제외한다. 기록 하나를 삭제하거나 전체 삭제한 뒤 새로고침해도 삭제된 기록이 다시 나타나지 않는다.
- 브라우저 저장값을 신뢰할 수 없는 이유: 사용자가 개발자 도구에서 저장값을 직접 수정하거나 삭제할 수 있고, 저장 공간 부족·개인정보 설정·브라우저 오류로 저장과 읽기가 실패할 수도 있다. 따라서 저장값이 항상 올바르거나 영구적으로 보존된다고 보장할 수 없다.
- 적용한 방어 방법: 버전과 ID를 확인하고, 질문 ID와 선택값이 유효한지 검사하며, 완료 시간과 결과 유형의 형식도 확인한다. 잘못된 JSON이나 형식의 기록은 기본값으로 처리하거나 제외한다. 저장소 접근에는 `try...catch`를 사용하고, 저장에 실패하면 현재 실행 중에만 임시 메모리를 사용하며 사용자에게 안내한다. 사용자 입력과 기록은 `textContent`로 출력하여 HTML이 실행되지 않게 했다.
